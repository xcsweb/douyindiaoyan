# 横屏口播成片 Spec

## Why

口播素材已经录完（8 段 / 1920×1080 / 共约 150 秒），但实际念的内容和我们预先写的稿子不一致；录屏素材也齐了，只是低配机器录出来有掉帧。直接拿旧稿去套模板必然对不上时间轴，需要以「真实录音」为唯一真源，先转写、再重排、再按模板的输入契约交付，避免反复返工。

## What Changes

- 固定一条横屏口播模板：`#336980 Modern Editorial · Narrated Explainer`（16:9 / 1920×1080 / 60fps / MIT / 5 个参数 / 离线渲染），只把它当版式与动效外壳，不改内容事实。
- 以实际录音为准做 ASR 转写，产出「旧稿 vs 实录」差异表，再重写口播文案与分段。
- 用 8 段口播拼出一条连续母版（裁头尾静音、统一响度），作为模板的唯一口播输入。
- 按母版真实语音生成 SRT，替代当前占位时间码。
- 录屏素材做卡顿处理：只取可用区间，必要时 0.85× 慢放 + 补帧；仍不达标则改用页面截图合成动效。
- 严格按 `https://motiongit.com/ai` 的流程：读 `00-START-HERE.md` 与 `assistant/guide.json` → 校验 → 读参数契约 → 预览 → 导出。
- 交付物落到 `横屏口播\03-成片\`：成片 MP4、SRT、素材与许可记录。

## Impact

- Affected specs: 无（新增能力，不改 `add-flowfield-art-tab`）
- Affected code:
  - `横屏口播\_work\`（转写、拼接、补帧脚本与中间产物）
  - `横屏口播\03-成片\`（成片、字幕、清单）
  - `口播文案-横屏.txt`、`横屏口播\拍摄清单.md`（按实录回写）
  - 不改 `community-photo\index.html`

## ADDED Requirements

### Requirement: 模板选型与合规
系统 SHALL 采用 `#336980 Modern Editorial · Narrated Explainer` 作为唯一横屏版式模板，并记录其版本号、许可与个人包信息。

#### Scenario: 模板确认
- **WHEN** 开始制作
- **THEN** 记录模板版本（当前 2.7.17-alpha.4）、输出规格（1920×1080 / 60fps）、MIT 许可与第三方素材的单独许可
- **AND** 不把个人包里的 API Key 写进任何交付文件、日志或对话

#### Scenario: 下载不可用
- **WHEN** 用户无法登录下载个人 `.motion` 包
- **THEN** 停在「内容与母版就绪、待套版」状态并明确告知，而不是用未经验证的替代方案冒充模板成片

### Requirement: 以实录为准的文案
系统 SHALL 以 8 段口播的实际语音为唯一真源，产出转写文本与差异表，重写后的文案不得与录音冲突。

#### Scenario: 转写与比对
- **WHEN** 对 `01-口播素材\` 的 8 个文件做语音识别
- **THEN** 输出逐段文本、时间码，以及「旧稿写了什么 / 实际说了什么」的差异表
- **AND** 技术事实（600 人、25×24、791 条连线、二分搜索、离屏画布）以实录为准，缺失的补进画面注释而不是硬塞回配音

### Requirement: 口播母版
系统 SHALL 把 8 段口播拼成一条连续母版，音画同步、无黑帧、无爆音，交付 1920×1080 / 30fps 母版供模板绑定。

#### Scenario: 拼接
- **WHEN** 按转写确认的顺序拼接
- **THEN** 每段裁掉头尾静音，段间保留 0.25—0.4 秒呼吸
- **AND** 全片响度统一到 -16 LUFS，峰值不超过 -1 dBTP
- **AND** 输出可被模板读取的容器与编码（H.264 + AAC）

#### Scenario: 素材不合格
- **WHEN** 某段画面糊、曝光跳变或台词说错
- **THEN** 标记该段并给出「重录 / 用别条备用 / 改成分屏图文」三种处理建议，不静默使用

### Requirement: 字幕与时间轴
系统 SHALL 按母版真实语音生成 SRT，时间码精确到毫秒，禁止沿用占位时间码。

#### Scenario: 字幕校对
- **WHEN** 母版定稿
- **THEN** SRT 的每条起止时间与语音对齐，误差不超过 120ms
- **AND** 专有名词统一（TRAE、1024、星流、主角秀、25×24）

### Requirement: 录屏卡顿处理
系统 SHALL 在不重录的前提下，把低配机器录制的卡顿素材处理到可剪辑水平。

#### Scenario: 掉帧素材
- **WHEN** 录屏片段的实际刷新不连续
- **THEN** 优先截取动作完整的区间，按 0.85× 慢放并用补帧重建 60fps
- **AND** 若补帧后仍有明显拖影或果冻感，改用同一形态的页面截图做位移/缩放动效替代

### Requirement: 模板套用与导出
系统 SHALL 严格按模板自带说明执行，不猜测参数、不虚构素材槽位。

#### Scenario: 按官方流程制作
- **WHEN** 拿到个人 `.motion` 包
- **THEN** 先列包内条目、读 `00-START-HERE.md` 与 `assistant/guide.json`，校验入口与完整性
- **AND** 只提取声明的工具文件到独立目录，运行 `node assistant/motion.mjs start <绝对路径>`
- **AND** 解包 `personal/`、`content/release.bin`、`core.enc` 一律不动

#### Scenario: 预览与导出
- **WHEN** 参数映射完成
- **THEN** 先出真实预览并逐段核对（口播画面位置、字卡内容、录屏插片时机）
- **AND** 再导出 1920×1080 / 60fps 成片，检查时长、音画同步、首尾黑帧、字幕烧录/外挂一致性

### Requirement: 交付归档
系统 SHALL 把成片、字幕、素材清单与许可记录集中到 `横屏口播\03-成片\`。

#### Scenario: 交付检查
- **WHEN** 成片导出完成
- **THEN** 目录内含 `master.mp4`、`master.srt`、`素材清单.md`（含模板版本、许可、素材来源）
- **AND** 更新 `口播文案-横屏.txt` 为实录版本，旧稿保留为对照
