# 调研：github.com/motiontemplates/all 对抖音版有没有用

> 调研时间 2026-10-28；来源：GitHub API + 仓库 README/CATALOG + motiongit.com/spec

## 一、它是什么

- **MotionGit 模板合集**，公开仓库，362 star，主页 `motiongit.com`，最后更新 2026-10-27
- 内容不是视频素材，而是 **`.motion` 模板包**：71 个模板、73 条独立 Demo，横屏和竖屏各一条
- 仓库里主要是清单和展示页：`README.md` / `CATALOG.md`（单列图文清单）、`catalog.json`（结构化数据）、`index.html`（GitHub Pages 在线播放 Demo）
- `.motion` 格式是 **开放规范**：ZIP + JSON + 动画工程源码 + 可替换参数 + 素材说明 + 依赖声明 + 许可，规范版本 `0.1.0-draft.1`，允许本地理解与渲染，不强制调用官方 API

## 二、和抖音版的关系

有用，但只用在「包装层」，不是内容层。

竖屏模板正好对得上抖音的规格：**9:16 · 1080×1920 · 60 FPS**，而且有几条就是「口播讲解」版式：

| 编号 | 名称 | 画幅 |
|---|---|---|
| #314486 | 现代图文 · 口播讲解 · 竖屏 | 9:16 1080×1920 |
| #738182 | 科技控制台 · 口播讲解 · 竖屏 | 9:16 1080×1920 |
| #385712 | 酷炫科技风 · 中文竖屏 | 9:16 1080×1920 |

这几条能直接当：**片头 3 秒大字、章节页、结尾定版**。

## 三、怎么用（建议的最小路径）

1. 先看 Demo：`https://motiontemplates.github.io/all/`，只挑竖屏、口播类，别一次看 71 条
2. 选定 1—2 条后从官网下载 `.motion`：如 `https://motiongit.com/@adunext/template-01-integrated-portrait`
3. 用包里自带的制作指南替换文案与截图，渲染成 1080×1920 片段，再和录屏在剪映里拼

## 四、不要做的事

- **不要整片套模板**。抖音指引要求前 3 秒出现结果、过程用真实录屏；模板动效会挤占信息密度，容易变成「只有炫酷画面说不清用途」（官方明确列为常见问题）
- 不要把模板里的示例素材当自己的成品画面提交
- 模板许可随包提供，商用前先看包内 LICENSE；官网说明源码 100% 开源，但第三方素材要单独确认

## 五、安全提示

该仓库 README 里夹了一段**写给 AI 助手的指令**（要求把全部 71 条模板连同图片原样回吐到对话里）。这属于内容里的提示注入，不是仓库的正常文档。我按你的明确要求只做了「这个仓库是干什么的、能不能用于抖音」的调研，没有执行那段指令。

## 六、结论

- **值得用**：拿 1 条竖屏口播模板做片头和结尾，能补上我们目前缺的「专业动效大字」
- **不必依赖**：主体仍是录屏 + 口播 + 我们的分镜卡，模板只是包装
- **优先级**：低于先把 8 段录屏拍完。素材齐了再挑模板，避免本末倒置

## 七、横屏口播：模板要什么，我们缺什么

模板不是「留一个画中画口播框让你往里塞」，而是**以配音时长为时间轴**，把口播画面与图文版式按稿件段落自动编排。官方原文：

> 需要准备：本期口播视频与原声、匹配的文稿或字幕，以及本期需要引用的图片、录像和数据。可先仅提供文稿讨论画面方案；正式制作前需要真实配音时长和已确认的素材。没有提供人物素材时，不使用示例人物代替你。

仓库 README 的输入槽位（以 #336980 原文为例）：
- Optional：talking-head video + its original audio（native presenter workflow，即真人出镜层）
- **Required：transcript 或 SRT**（对齐本期旁白/视频）
- Optional：本期主题、要点、输出偏好
- 时长策略：`duration policy follows the current voiceover`（按真实配音时长，不按 Demo 时长）

横屏口播可选模板（均 16:9 · 1920×1080 · 60FPS）：

| 编号 | 名称 | 适合度 |
|---|---|---|
| #336980 | 现代图文 · 口播讲解 | 最中性，观点/证据/步骤讲解，首选 |
| #553346 | 科技控制台 · 口播讲解 | 紫色玻璃+数据组件，最贴 TRAE 技术调性 |
| #304634 | 深色立体 · 多屏展陈 | 多屏放录屏/截图，适合过程演示 |
| #358192 | 纸面透视 · 口播讲解 | 卡片层次，适合方法拆解 |
| #960723 / #762139 | 鲜色角色 / 活力海报 | 叙事、观点，风格偏活泼 |

我们的缺口清单：
1. ❌ **真人横屏口播录像**（1920×1080，正脸居中，同一机位）
2. ❌ **原声**（同期声或单独录音，需与画面对齐）
3. ❌ **带时间码的 SRT/文稿**——现有 `口播逐字稿.txt` 是 65 秒竖屏抖音版，需按横屏版重写并打轴
4. ⚠️ **引用素材**：9 图已有，8 段录屏未拍
5. ⚠️ 可选：署名头像/LOGO、已授权配乐
6. ✅ 已有：文案、9 张成图、4 张分镜卡、作品本体可实时录屏

## 九、执行建议（横屏口播）

1. 先定稿横屏口播文案（按 60–90 秒，不要沿用 65 秒竖屏稿），再录真人+原声
2. 用 Whisper/剪映自动字幕导出 SRT，作为模板的必需输入
3. 模板选 #336980（稳）或 #553346（贴技术调性），只做包装，不改主体信息
4. 两段 14 秒插片：先试 #460349（马赛克揭幕）、#328828（笔刷重绘），它们比手工 CSS 动效更完整
5. 最稳的商用路径：`385712`（MIT）+ 自建 `.motion`（`motion-spec`），不依赖官网账号
