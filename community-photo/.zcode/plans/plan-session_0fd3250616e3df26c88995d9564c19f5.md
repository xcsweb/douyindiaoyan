# 工作流方案：TRAE 社区 1024 全家福 — tab 流畅度优化 + 重拉社区数据

## 探索结论（已由两个只读探查代理完成）

**项目管线**： `fetch.mjs`（从 forum.trae.cn 抓成员/头像/话题 → 生成 `data.js`，600 人，头像为内嵌 base64）→ `build-single.mjs`（把 `index.html` + `data.js` 内联成单文件 `TRAE社区1024全家福.html`）。页面本身零运行时请求。

**Tab 卡顿根因（已定位，按影响排序）**：
1. `textSlots()` 在点击路径里同步做舞台尺寸画布光栅化 + `getImageData`（多 MB GPU→CPU 回读），倒计时 tab 每秒还重算一次；
2. 600 个 `will-change` 图层同时做带 box-shadow/边框的 CSS 过渡（每次切 tab 约 1 秒的合成风暴）；
3. 每次点击多次强制重排（`void flash.offsetWidth`、样式批量写入后读 `clientWidth`）；
4. 每次 `apply()` 全画布重绘背景（3 层径向渐变 + ~800 个星点弧）；
5. 进星座 tab 时 O(n²) `computeEdges()`（36 万次距离计算 + 超大 SVG path）；
6. 倒计时 tab 每 8 秒自动轮换的主角模式有同步 CPU 重活（最高精度 144 万次颜色匹配，缓存超 40 条即清空）；
7. 星流 tab 进入时重建画廊 DOM + 前 0.7 秒 DOM 模式掉帧（FPS 看门狗之后才切 WebGL）。

**头像**： 当前 600 人已全部是真实图片 data-URL（抓取器直接丢弃下载不到头像的用户）。"尽量选有图片的"落在 fetch.mjs 的**成员筛选逻辑**：重拉时优先选择有真实上传头像（排除 Discourse letter_avatar 默认字母头像）的成员，总数保持 600，不够时再用字母头像用户补足并如实报告。

## 工作流设计（CreateWorkflow，4 个子代理，6 个阶段）

**阶段 1「重新拉取社区数据，优先选择有真实头像的成员」与阶段 2「优化五个 tab 的切换流畅度」并发执行**（分别改 fetch.mjs 和 index.html，互不冲突）：

- **数据工程师**：修改 fetch.mjs 筛选逻辑（偏好真实上传头像、保持总量 600），随后脚本以 `world.run` 执行 `node fetch.mjs` 和 `node fetch.mjs --enrich=true` 作为确定性门控（各 ≤10 分钟超时，失败把 stderr 回馈给数据工程师修复，各最多重试 2 轮），再用 `node -e` 统计新生成 data.js 的人数/头像比例并上报。
- **交互性能工程师**：按上述 7 条根因清单优化 index.html（缓存/复用 textSlots 结果、消除点击路径强制重排、缓存背景绘制、星座连线空间网格化或预计算、主角模式缓存策略、星流提前走 WebGL、过渡期间的图层开销控制等），要求视觉与全部功能不变、尊重 prefers-reduced-motion 与现有 WebGL 回退。

**阶段 3「合成单文件并做快速检查」**： join 后 `node build-single.mjs`（失败修复重试），再跑两条已在方案中定稿的 `node -e` 门控：index.html 全部 `<script>` 语法解析检查、data.js 统计解析。

**阶段 4「浏览器实测五个 tab，有问题就修」**： **浏览器测试员**（browser-use）本地起静态服务打开合成后的单文件，逐个点击 5 个 tab、等主角模式自动轮换、试搜索，收集 console 报错并截图，可选做 rAF 帧率探测；发现问题 → 交互性能工程师修复 → 重新合成，最多 3 轮。

**阶段 5「独立复审全部改动」**： **独立评审员**（未参与编写的全新上下文，只读）对照功能清单（5 种模式、主角轮换、搜索、缩放、reduced-motion、WebGL 回退、窗口 resize）复审 index.html 与 fetch.mjs 改动；必须修复的问题 → 工程师修复 → 重新合成 → 测试员快速回归。

**阶段 6「交付单文件与报告」**： `artifact.file` 发布优化后的 `TRAE社区1024全家福.html`（primary 交付物）+ `artifact.markdown` 优化与数据更新报告，返回标准 WorkflowReport（结论、发现、已验证项、未覆盖项，均中文）。

## 约定与假设

- 成员总数保持 600（页面横幅宣称"600 位 Builder"）；不足 600 个真实头像成员时用字母头像用户补足并在报告中说明。
- 只改 fetch.mjs / index.html（data.js、单文件为生成物），不动视觉设计与既有功能。
- 依赖本机已有 Node.js（项目本身用 node 脚本构建）。

## 批准后执行动作
